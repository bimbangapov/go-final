# TODO App

Учебное веб-приложение для управления задачами, разработанное на Go.

Приложение позволяет создавать, редактировать, удалять и завершать задачи, а также настраивать их периодическое выполнение.

## Технологии

- **Go** — серверная часть приложения.
- **Chi** — HTTP-маршрутизация и middleware.
- **SQLite** — хранение задач.
- **JWT** — авторизация пользователей.

## Переменные окружения

Для настройки приложения используются следующие переменные окружения:

| Переменная | Описание | Пример         |
|------------|----------|----------------|
| `TODO_PORT` | Порт HTTP-сервера | `7540`         |
| `TODO_DBFILE` | Путь к файлу базы данных SQLite | `scheduler.db` |
| `TODO_PASSWORD` | Пароль для авторизации и секрет подписи JWT<br/>Если не задать пароль через переменную окружения, усиаервмися паротль по умолчанию:<br/> `qwerty12345` | `qwerty12345`  |

> При включённой авторизации переменная `TODO_PASSWORD` должна иметь одинаковое значение при запуске сервера и тестов.
>
> Тесты используют пароль для генерации JWT, который затем проверяется сервером.
>
> Если значения `TODO_PASSWORD` отличаются, сервер не сможет проверить подпись токена и вернёт `401 Unauthorized`.

## Запуск приложения
Приложение поддерживает два способа запуска:
- Через Docker (рекомендуемый способ).
- Локально с использованием Go.

### Переменные окружения

Для настройки приложения используются следующие переменные:

| Переменная | Описание | Пример |
|------------|----------|--------|
| `TODO_PORT` | Порт HTTP-сервера | `7540` |
| `TODO_DBFILE` | Путь к файлу базы данных SQLite | `scheduler.db` |
| `TODO_PASSWORD` | Пароль для авторизации и секрет подписи JWT | `qwerty12345` |

### 1. Запуск через Docker

Готовый образ опубликован в Docker Hub:

[Docker Hub — TODO App](https://hub.docker.com/r/bimbangapov95/todo-app)

Для запуска необходимо установить Docker.

**Шаг 1. Создать директорию для хранения базы данных**

```bash
mkdir -p data
```

**Шаг 2. Скачать Docker-образ**

```bash
docker pull bimbangapov95/todo-app
```

**Шаг 3. Запустить контейнер**

```bash
docker run -d \
  --name go-final \
  -p 7540:7540 \
  -e TODO_PORT=7540 \
  -e TODO_PASSWORD=qwerty12345 \
  -e TODO_DBFILE=/data/scheduler.db \
  -v "$(pwd)/data:/data" \
  bimbangapov95/todo-app:1.1.0
```

После запуска приложение доступно по адресу:

http://localhost:7540

**Хранение данных**

Для хранения SQLite используется Bind Mount:

```text
Хост:        ./data/scheduler.db
Контейнер:   /data/scheduler.db
```

База данных физически хранится на компьютере пользователя.

При остановке, удалении или пересоздании контейнера данные сохраняются.

### 2. Локальный запуск

Для локального запуска необходимо установить Go.

**Шаг 1. Клонировать репозиторий**

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd go-final
```

**Шаг 2. Установить зависимости**
```bash
go mod download
```

**Шаг 3. Собрать прилодение **

```bash
go build -o app.exe ./main.go                                                      
```

**Шаг 4. Запустить приложение**

```bash

TODO_PASSWORD=qwerty12345 \
go run app.exe
```

После запуска приложение доступно по адресу:

http://localhost:7540

## Авторизация

Для авторизации используется метод `POST /api/signin`.

После успешной проверки пароля сервер возвращает JWT со сроком действия **8 часов**.

Токен передаётся в cookie `token` при обращении к защищённым API-методам.

### 3. Запуск тестов

Интеграционные тесты выполняют HTTP-запросы к работающему приложению.

Поэтому перед запуском тестов необходимо запустить сервер.

**Важно:** переменная `TODO_PASSWORD` должна иметь одинаковое
значение при запуске сервера и тестов.

Пример запуска тестов:

```bash
TODO_PORT=7540 \
TODO_PASSWORD=qwerty12345 \
go test ./tests -v
```

> [!WARNING]
> Некоторые тесты изменяют и удаляют данные в базе.
> Рекомендуется выполнять тестирование с отдельной тестовой БД.
>
> Для успешного выполнения тестов пароль сервера
> и пароль тестов должны совпадать.
