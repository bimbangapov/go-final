## GET /api/nextdate
### Метод расчёта следующей даты выполнения задачи

#### Входные параметры
**Query:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| now | Нет | Текущая дата в формате `YYYYMMDD`. Если не передана, используется текущая системная дата |
| date | Да | Исходная дата выполнения задачи в формате `YYYYMMDD` |
| repeat | Да | Правило повторения задачи |

#### Описание
Метод предназначен для расчёта следующей даты выполнения задачи
на основании исходной даты, текущей даты и правила повторения.

Метод не изменяет данные в БД и используется только для вычисления даты.

#### Выходные параметры
**Body:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| date | Да | Рассчитанная дата следующего выполнения задачи в формате `YYYYMMDD` |

**Формат ответа:** `text/plain`

#### Пример запроса

```http
GET /api/nextdate?now=20261013&date=20261013&repeat=d%201
```

**Расшифровка параметров:**

- `now=20261013` — текущая дата 13.10.2026.
- `date=20261013` — исходная дата задачи 13.10.2026.
- `repeat=d 1` — повторение задачи каждый день.

#### Пример ответа

**HTTP 200 OK**

```text
20261014
```

#### Ошибки

| HTTP-код | Описание |
|----------|----------|
| 200 | Дата успешно рассчитана |
| 400 | Переданы некорректные параметры или правило повторения |

## GET /api/task
### Метод получения задачи по идентификатору

#### Входные параметры

**Query:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| id | Да | Числовой идентификатор задачи |

**Cookie:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| token | Условно | JWT-токен авторизации. Обязателен при включённой авторизации |

#### Описание

Метод предназначен для получения информации о конкретной задаче
по её уникальному идентификатору.

При получении HTTP-запроса выполняются следующие действия:

1. Проверка авторизации пользователя через `AuthMiddleware`.
2. Получение параметра `id` из Query.
3. Проверка наличия идентификатора.
4. Преобразование идентификатора в числовой тип.
5. Выполнение SQL-запроса для поиска задачи по идентификатору.
6. Формирование JSON-ответа с информацией о найденной задаче.

## POST /api/task
### Метод создания новой задачи

#### Входные параметры

**Body:**

| Параметр | Тип | Обязательность | Описание |
|----------|-----|----------------|----------|
| date | string | Нет | Дата выполнения задачи в формате `YYYYMMDD`. Если не указана, используется текущая дата |
| title | string | Да | Наименование задачи |
| comment | string | Нет | Дополнительное описание задачи |
| repeat | string | Нет | Правило повторения задачи |

**Cookie:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| token | Условно | JWT-токен авторизации. Обязателен при включённой авторизации |

#### Описание

Метод предназначен для создания новой задачи и сохранения
информации о ней в базе данных SQLite.

При получении HTTP-запроса выполняются следующие действия:

1. Проверка авторизации пользователя через `AuthMiddleware`.
2. Получение JSON из тела HTTP-запроса.
3. Десериализация JSON в структуру задачи.
4. Проверка корректности входных параметров.
5. Проверка и корректировка даты выполнения задачи.
6. Проверка правила повторения задачи.
7. Сохранение задачи в базу данных SQLite.
8. Получение идентификатора созданной задачи.
9. Формирование JSON-ответа с идентификатором задачи.

**Особенности обработки даты:**

- Если дата не указана, используется текущая дата.
- Если указана прошедшая дата, она корректируется с учётом правила повторения.
- Если правило повторения отсутствует, задача считается однократной.

#### Выходные параметры

**Body:**

| Параметр | Тип | Обязательность | Описание |
|----------|-----|----------------|----------|
| id | string | Да | Уникальный идентификатор созданной задачи |

**Формат ответа:** `application/json`

#### Пример запроса

```http
POST /api/task
Content-Type: application/json
Cookie: token=<JWT>
```

**Body:**

```json
{
  "date": "20261015",
  "title": "Купить продукты",
  "comment": "Молоко, хлеб, яйца",
  "repeat": "d 3"
}
```

#### Пример успешного ответа

**HTTP 200 OK**

```json
{
  "id": "15"
}
```

## GET /api/tasks
### Метод получения списка задач

#### Входные параметры

**Query:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| search | Нет | Строка поиска для фильтрации задач |

**Cookie:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| token | Условно | JWT-токен авторизации. Обязателен при включённой авторизации |

#### Описание

Метод предназначен для получения списка задач,
сохранённых в базе данных SQLite.

Метод поддерживает получение полного списка задач
и фильтрацию по поисковому запросу.

При получении HTTP-запроса выполняются следующие действия:

1. Проверка авторизации пользователя через `AuthMiddleware`.
2. Получение необязательного Query-параметра `search`.
3. Определение условий выборки задач.
4. Формирование и выполнение SQL-запроса к SQLite.
5. Получение списка задач из базы данных.
6. Формирование JSON-ответа с массивом задач.

**Body:**

| Параметр | Тип | Обязательность | Описание |
|----------|-----|----------------|----------|
| tasks | array | Да | Массив задач |

## POST /api/task/done
### Метод завершения задачи

#### Входные параметры

**Query:**

| Параметр | Тип | Обязательность | Описание |
|----------|-----|----------------|----------|
| id | int | Да | Уникальный идентификатор завершаемой задачи |

**Cookie:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| token | Условно | JWT-токен авторизации. Обязателен при включённой авторизации |

#### Описание

Метод предназначен для завершения задачи.

При завершении задачи выполняется проверка правила повторения `repeat`.

В зависимости от значения `repeat` выполняется одно из двух действий:

1. **Однократная задача** — удаляется из базы данных.
2. **Повторяющаяся задача** — рассчитывается следующая дата выполнения, после чего обновляется запись в БД.

При получении HTTP-запроса выполняются следующие действия:

1. Проверка авторизации пользователя через `AuthMiddleware`.
2. Получение идентификатора задачи `id` из Query-параметров.
3. Проверка корректности идентификатора.
4. Получение задачи из базы данных по идентификатору.
5. Проверка наличия правила повторения `repeat`.
6. Выполнение операции завершения задачи:
    - При отсутствии правила повторения — удаление задачи.
    - При наличии правила повторения — расчёт следующей даты выполнения.
7. Обновление или удаление записи в SQLite.
8. Формирование HTTP-ответа.

#### Логика завершения задачи

**Однократная задача**

Если параметр `repeat` содержит пустую строку, задача удаляется из БД.

**Пример задачи до завершения:**

```json
{
  "id": "15",
  "date": "20261014",
  "title": "Купить продукты",
  "comment": "Молоко, хлеб, яйца",
  "repeat": ""
}
```

После успешного выполнения метода запись с `id = 15` удаляется из таблицы `scheduler`.

**Повторяющаяся задача**

Если параметр `repeat` содержит правило повторения, задача не удаляется.

Вместо удаления выполняется расчёт следующей даты выполнения с использованием правила `repeat`.

После расчёта обновляется поле `date` существующей задачи.

**Пример задачи до завершения:**

```json
{
  "id": "15",
  "date": "20261014",
  "title": "Купить продукты",
  "comment": "Молоко, хлеб, яйца",
  "repeat": "d 3"
}
```

Предположим, задача завершается 14.10.2026.

После завершения дата выполнения переносится на 17.10.2026.

**Состояние задачи после завершения:**

```json
{
  "id": "15",
  "date": "20261017",
  "title": "Купить продукты",
  "comment": "Молоко, хлеб, яйца",
  "repeat": "d 3"
}
```

> [!NOTE]
> При завершении повторяющейся задачи сохраняется её идентификатор.
> Изменяется только дата следующего выполнения.
>
> Следующая дата определяется с учётом текущей даты,
> исходной даты задачи и установленного правила повторения.


#### Выходные параметры

При успешном завершении задачи метод возвращает пустой JSON-объект.

**Формат ответа:** `application/json`

#### Пример запроса

```http
POST /api/task/done?id=15
Cookie: token=<JWT>
```

#### Пример успешного ответа

**HTTP 200 OK**

```json
{}
```
