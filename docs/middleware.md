# Middleware

## AuthMiddleware
### Промежуточный обработчик авторизации пользователя

#### Назначение
`AuthMiddleware` предназначен для проверки JWT-токена пользователя
перед предоставлением доступа к защищённым API-методам приложения.

Middleware реализован с использованием библиотеки `golang-jwt/jwt/v5`.

#### Входные параметры

**Cookie:**

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| token | Да | JWT-токен авторизации пользователя |

**Пример HTTP-запроса:**

```http
GET /api/tasks HTTP/1.1
Host: localhost:7540
Cookie: token=eyJhbGciOiJIUzI1NiJ9...
```

#### Описание

Middleware выполняет проверку JWT-токена перед передачей
HTTP-запроса целевому обработчику.

Токен предварительно выдаётся пользователю методом
`POST /api/signin` после успешной аутентификации.

При получении запроса выполняются следующие действия:

1. Получение JWT-токена из cookie `token`.
2. Проверка наличия токена.
3. Проверка алгоритма подписи `HS256`.
4. Проверка цифровой подписи JWT с использованием серверного секрета.
5. Проверка наличия срока действия токена (`exp`).
6. Проверка актуальности срока действия токена.
7. Передача запроса целевому обработчику при успешной авторизации.

Если токен отсутствует, повреждён, имеет некорректную подпись
или истёк срок его действия, запрос отклоняется.

**Время жизни JWT:** 8 часов с момента создания.

#### Выходные параметры

Middleware не формирует тело успешного HTTP-ответа.

При успешной проверке JWT управление передаётся
следующему HTTP-обработчику.

При неуспешной проверке возвращается ошибка.

| HTTP-код | Описание |
|----------|----------|
| 401 | Токен отсутствует или не прошёл проверку |

#### Защищённые API-методы

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/task` | Получение задачи |
| POST | `/api/task` | Создание задачи |
| GET | `/api/tasks` | Получение списка задач |
| PUT | `/api/task` | Изменение задачи |
| DELETE | `/api/task` | Удаление задачи |
| POST | `/api/task/done` | Завершение задачи |

#### Публичные API-методы

Следующие методы не требуют прохождения `AuthMiddleware`.

| Метод | Endpoint | Описание |
|-------|----------|----------|
| POST | `/api/signin` | Аутентификация пользователя |
| GET | `/api/nextdate` | Расчёт следующей даты выполнения задачи |

#### Особенности реализации

- Middleware подключается через `chi.Router`.
- Используется алгоритм подписи `HS256`.
- JWT содержит стандартный claim `exp`.
- Проверка подписи и срока действия выполняется библиотекой `golang-jwt/jwt/v5`.
- JWT не сохраняется в базе данных.
- Авторизация выполняется при каждом обращении к защищённому API-методу.


## LoggingMiddleware
### Промежуточный обработчик логирования HTTP-запросов

#### Назначение

`LoggingMiddleware` предназначен для регистрации входящих
HTTP-запросов к приложению.

Middleware используется для отслеживания обращений к HTTP-серверу
и получения информации о вызываемых API-методах и ресурсах.
